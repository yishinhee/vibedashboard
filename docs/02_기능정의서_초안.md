## 1. 시스템 개요

### 1.1 목적

Claude Code 하네스가 적용된 프로젝트들의 **기능정의.md, 프로그램구조.md, uiux개선.md, feature_map.md** 파일을 읽어 구조화된 데이터로 변환하고, 여러 프로젝트의 진행 상황을 한 화면에서 파악하는 관리 도구.

### 1.2 핵심 사용 시나리오

```
1. 프로젝트 폴더를 등록한다.
2. 대시보드가 해당 폴더의 docs/ 파일들을 파싱해서 DB 에 저장한다.
3. 이후 파일이 변경되면 "동기화" 버튼 클릭 또는 자동 감지로 갱신한다.
4. 여러 프로젝트의 Phase 진행률, 미완료 DoD, 기능 구현 현황을 한 눈에 본다.
```

### 1.3 표시 원칙

**표시한다:**
- 현재 진행 중인 Phase 와 완료율
- 미완료 DoD / pending_updates 항목 수
- 미구현 기능(F-*) 목록
- 마지막 동기화 시각과 변경 여부

**표시하지 않는다:**
- 코드 라인 수, 커밋 횟수 등 개발 생산성 수치
- 파이차트 기반 완료율 (숫자 텍스트로 충분)
- 의미없는 "활동 지수" 류의 통계

## 4. 데이터 모델 (SQLite 스키마)

### 4.1 설계 원칙

- 원본 md 파일 형식이 프로젝트마다 달라도 파싱 레이어만 수정하면 됨
- raw_text 필드로 파싱 실패 시 원문 복구 가능
- mtime 으로 변경 감지, 불필요한 재파싱 방지

### 4.2 테이블 명세

#### Project (프로젝트)
```sql
CREATE TABLE project (
    id          INTEGER PRIMARY KEY,
    name        TEXT NOT NULL,           -- 프로젝트명
    path        TEXT NOT NULL UNIQUE,    -- 절대 경로 (예: C:\Users\shinh\projects\inidk)
    description TEXT,
    last_synced_at DATETIME,            -- 마지막 동기화 시각
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    deleted_at  DATETIME                -- 소프트 딜리트
);
```

#### Screen (화면 ID)
```sql
CREATE TABLE screen (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES project(id),
    screen_id   TEXT NOT NULL,          -- SCR-BNK-01
    category    TEXT,                   -- 임상자원은행, 게시판 등
    name        TEXT,                   -- 화면명
    url         TEXT,                   -- URL 패턴
    raw_text    TEXT                    -- 원문 (파싱 실패 복구용)
);
```

#### Feature (기능 ID)
```sql
CREATE TABLE feature (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES project(id),
    screen_id   TEXT,                   -- 연결된 SCR-*
    feature_id  TEXT NOT NULL,          -- F-BNK-01
    name        TEXT,
    status      TEXT DEFAULT 'unknown', -- implemented / not_implemented / unknown
    priority    TEXT,                   -- P0/P1/P2/P3
    raw_text    TEXT
);
```

#### AppModule (앱 모듈)
```sql
CREATE TABLE app_module (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES project(id),
    app_name    TEXT NOT NULL,          -- boards, biobank 등
    responsibility TEXT,                -- 앱 책임 설명
    model_count INTEGER DEFAULT 0,
    service_count INTEGER DEFAULT 0,
    raw_text    TEXT
);
```

#### Phase (Phase 정보)
```sql
CREATE TABLE phase (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES project(id),
    phase_num   INTEGER,                -- 1, 2, 3 ...
    name        TEXT,                   -- Phase 1 — 기반 설정
    status      TEXT DEFAULT 'pending', -- done / in_progress / pending
    total_items INTEGER DEFAULT 0,
    done_items  INTEGER DEFAULT 0
);
```

#### ChecklistItem (Phase 체크리스트)
```sql
CREATE TABLE checklist_item (
    id          INTEGER PRIMARY KEY,
    phase_id    INTEGER REFERENCES phase(id),
    project_id  INTEGER REFERENCES project(id),
    priority    TEXT,                   -- P0/P1/P2/P3
    content     TEXT NOT NULL,
    is_done     INTEGER DEFAULT 0,      -- 0: 미완료, 1: 완료
    raw_text    TEXT
);
```

#### ImprovementItem (P0~P3 개선 항목)
```sql
CREATE TABLE improvement_item (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES project(id),
    priority    TEXT NOT NULL,          -- P0/P1/P2/P3
    title       TEXT NOT NULL,
    description TEXT,
    phase_target TEXT,                  -- 구현 예정 Phase
    is_done     INTEGER DEFAULT 0,
    raw_text    TEXT
);
```

#### FeatureMap (기능↔파일↔DB 매핑)
```sql
CREATE TABLE feature_map (
    id            INTEGER PRIMARY KEY,
    project_id    INTEGER REFERENCES project(id),
    feature_id    TEXT,                 -- F-BNK-01
    feature_name  TEXT,
    entry_point   TEXT,                 -- URL 또는 명령
    view_handler  TEXT,                 -- 파일경로:함수명
    service       TEXT,                 -- 서비스 파일:함수명
    model_db      TEXT,                 -- 테이블명 (필드)
    template_ui   TEXT,
    external_api  TEXT,
    raw_text      TEXT
);
```

#### SyncLog (동기화 이력)
```sql
CREATE TABLE sync_log (
    id          INTEGER PRIMARY KEY,
    project_id  INTEGER REFERENCES project(id),
    synced_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    file_name   TEXT,                   -- 파싱한 파일명
    file_mtime  DATETIME,               -- 파일 수정 시각
    changed     INTEGER DEFAULT 0,      -- 변경 여부
    result      TEXT,                   -- success / failed / no_change
    detail      TEXT                    -- 오류 내용 또는 파싱 요약
);
```

## 5. 파싱 전략

### 5.1 파싱 레이어 구조

```
apps/dashboard/services/
├── parser/
│   ├── base_parser.py        -- 공통 인터페이스
│   ├── feature_parser.py     -- 기능정의.md 파싱
│   ├── structure_parser.py   -- 프로그램구조.md 파싱
│   ├── improvement_parser.py -- uiux개선.md 파싱
│   ├── design_parser.py      -- 프로젝트설계.md 파싱
│   └── feature_map_parser.py -- feature_map.md 파싱
└── sync_service.py           -- 동기화 오케스트레이션
```

### 5.2 파일별 파싱 규칙

#### 기능정의.md
```python
# SCR-* 추출
패턴: | SCR-{코드} | {구분} | {화면명} | {URL} |
예시: | SCR-BNK-01 | 임상자원은행 | 임상자원 확보 목록 | /biobank/resources/ |

# F-* 추출
패턴: | F-{코드} | {기능명} | {화면} | {상세} |
예시: | F-BNK-01 | 임상자원 목록 조회 | SCR-BNK-01 | ... |
```

#### uiux개선.md
```python
# 개선 항목 추출
패턴: ### [P{n}] {제목}  또는  ### ✅ [P{n}] {제목}
완료: ✅ 가 앞에 붙어있으면 is_done=1

# Phase 체크리스트 추출
패턴: ### Phase {n} — {설명}
항목: - ✅ {내용}  →  is_done=1
      - [ ] {내용}  →  is_done=0
```

#### 프로그램구조.md
```python
# 앱 추출
패턴: ## N. apps/{앱명}/  또는 ### {앱명} 앱

# 모델 추출
패턴: class {ModelName} 또는 테이블명 셀 (| 모델명 |)

# 서비스 함수 추출
패턴: def {func_name} 또는 | {함수명} | 형태의 테이블
```

#### 변경 감지
```python
# mtime 비교
import os
file_mtime = os.path.getmtime(filepath)
last_mtime = SyncLog.objects.filter(
    project=project, file_name=filename
).order_by('-synced_at').first()

if last_mtime and last_mtime.file_mtime == file_mtime:
    return "no_change"  # 재파싱 불필요
```
