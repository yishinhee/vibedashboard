## 1. apps/projects/ — 프로젝트 등록 관리

### 책임
- Project 모델 CRUD (소프트 딜리트 정책)
- 등록 시 폴더 경로 검증 + docs/ 하위 필수 파일 존재 확인
- 등록 직후 최초 동기화 트리거 (`apps.sync.services.sync_service.sync_project` 호출)

### 모델
| 모델 | 테이블 | 주요 필드 |
|---|---|---|
| Project | `project` | `path`(unique), `name`, `description`, `last_synced_at`, `created_at`, `updated_at`, `deleted_at` |

- 매니저: `Project.objects` (전체) / `Project.active` (`deleted_at IS NULL` 만)
- 메서드: `soft_delete()` — `deleted_at` set + `update_fields=['deleted_at','updated_at']`
- 인덱스: `idx_project_active` 부분 인덱스 (`deleted_at IS NULL`)

### URL
| URL | name | 뷰 |
|---|---|---|
| `/projects/add/` | `projects:create` | `project_create` |
| `/projects/<id>/edit/` | `projects:update` | `project_update` |
| `/projects/<id>/delete/` | `projects:delete` | `project_delete` |

### 서비스
| 함수 | 파일 | 책임 |
|---|---|---|
| `list_active()` | `services/project_service.py` | `deleted_at IS NULL` 만 반환 |
| `create_with_initial_sync(payload)` | `services/project_service.py` | 검증 → 생성 → 최초 sync |
| `update(project, payload)` | `services/project_service.py` | 부분 업데이트 |
| `soft_delete(project)` | `services/project_service.py` | `deleted_at` set + cascade row 삭제 |
| `get_pending_count(project)` | `services/project_service.py` | 외부 폴더 `tmp/pending_updates.json` 항목 수 반환 |

## 2. apps/parsers/ — md 파싱 서비스

### 책임
- 등록된 외부 프로젝트의 docs/*.md 파일을 읽어 구조화된 dict 또는 ORM row 로 변환
- 파싱 실패 시 raw_text 보존, 예외 throw 금지
- **외부 파일은 read-only**. 어떤 경우에도 쓰지 않는다.

### 모듈
| 파일 | 책임 |
|---|---|
| `services/base_parser.py` | 추상 `BaseParser` 클래스. `parse(text:str) -> dict` 시그니처 정의 |
| `services/feature_parser.py` | 기능정의.md → Screen, Feature |
| `services/structure_parser.py` | 프로그램구조.md → AppModule, ModelInfo |
| `services/improvement_parser.py` | uiux개선.md → ImprovementItem, ChecklistItem |
| `services/design_parser.py` | 프로젝트설계.md → Phase |
| `services/feature_map_parser.py` | feature_map.md → FeatureMap |

### 파서 레지스트리
```python
# apps/parsers/services/__init__.py
PARSER_REGISTRY = {
    "기능정의.md":   FeatureParser,
    "프로그램구조.md": StructureParser,
    "uiux개선.md":  ImprovementParser,
    "프로젝트설계.md": DesignParser,
    "feature_map.md": FeatureMapParser,
}
```

## 4. apps/sync/ — 동기화 오케스트레이션

### 책임
- mtime 비교 → 변경된 파일만 파서 호출 → SyncLog 기록
- 관리 명령어 `sync_project`, `sync_all` 제공

### 모델
| 모델 | 테이블 |
|---|---|
| SyncLog | `sync_log` |

### URL
| URL | name | 뷰 |
|---|---|---|
| `POST /projects/<id>/sync/` | `sync:run` | `sync_now` |
| `/projects/<id>/sync/` | `sync:log` | `sync_log_list` |

### 서비스
| 함수 | 파일 | 책임 |
|---|---|---|
| `sync_project(project)` | `services/sync_service.py` | 등록된 5개 파일 순차 sync |
| `sync_one_file(project, filename)` | `services/sync_service.py` | mtime 비교 → 파서 호출 → SyncLog 기록 |

### 관리 명령어
| 명령어 | 파일 |
|---|---|
| `python manage.py sync_project <id>` | `management/commands/sync_project.py` |
| `python manage.py sync_all` | `management/commands/sync_all.py` |

## 5. config/ — Django 설정

```
config/
├── __init__.py
├── settings/
│   ├── __init__.py    # 빈 패키지 마커
│   ├── base.py        # 공통 (django-environ 으로 .env 로드, ko-kr/Asia/Seoul, templates/static, INSTALLED_APPS)
│   ├── dev.py         # DEBUG=True 강제, ALLOWED_HOSTS 안전망, INTERNAL_IPS
│   └── prod.py        # DEBUG=False, ALLOWED_HOSTS 누락 시 RuntimeError, 보안 헤더
├── urls.py            # ROOT URLConf
├── wsgi.py            # 기본 settings: config.settings.prod
└── asgi.py            # 기본 settings: config.settings.prod
```

- `manage.py` 기본 settings: `config.settings.dev`
- `.env` 의 `DJANGO_SETTINGS_MODULE` 환경변수로 override 가능
