## 2. Phase 별 상세

### Phase 1 — 데이터 레이어

**목표**: 외부 프로젝트의 docs/*.md 를 파싱해 SQLite 에 저장하는 백엔드 완성.

**핵심 작업**
1. Django 프로젝트 초기화 (`django-admin startproject config .`)
2. 4개 앱 생성 (`projects`, `parsers`, `dashboard`, `sync`)
3. 모델 9종 정의 + 마이그레이션
4. `BaseParser` + 5개 파일별 파서 구현
5. `sync_service` mtime 비교 로직
6. 파서별 fixture(`tests/fixtures/*.md`) 기반 단위 테스트

**완료 기준**
- `python manage.py test apps.parsers` 6개 파서 모두 통과
- `sync_one_file` 통합 테스트: 동일 파일 두 번 호출 시 두 번째는 `no_change` 반환

### Phase 2 — 프로젝트 관리 화면

**목표**: 사용자가 프로젝트 폴더를 등록·편집·삭제할 수 있다.

**핵심 작업**
1. `templates/base.html` Tailwind 레이아웃 (좌측 사이드바, 우측 콘텐츠)
2. `dashboard/project_list.html` + `_project_card.html` 부분 템플릿
3. `projects/project_form.html` 등록/편집
4. 폴더 경로 검증 (존재 여부, `docs/` 하위 파일 확인)
5. 소프트 삭제 확인 모달

**완료 기준**
- 정상 폴더 등록 시 최초 sync 가 자동 실행되어 SyncLog 5건(파일 수만큼) 생성
- 잘못된 경로 등록 시 알림 메시지 표시 + DB 에 row 생성되지 않음

### Phase 3 — 상세 4개 탭

**목표**: 등록된 프로젝트의 4가지 측면(기능/Phase/구조/개선)을 탭으로 표시.

**핵심 작업**
1. 4개 탭 뷰 + 템플릿
2. 앱별·우선순위·완료 상태 필터 (querystring 기반)
3. 미구현·미완료 항목 색상 구분 (Tailwind utility)
4. 탭 네비 부분 템플릿(`_tab_nav.html`) 으로 4개 탭 공유

**완료 기준**
- 각 탭에서 필터 변경 시 URL querystring 이 갱신되고 새로고침해도 상태 유지
- INID-K 등 실제 프로젝트 등록 후 4개 탭에서 데이터가 정확히 표시됨

### Phase 4 — 동기화 고도화

**목표**: 수동 동기화 + 변경 감지 + 동기화 이력 화면.

**핵심 작업**
1. HTMX 기반 수동 동기화 버튼 (페이지 새로고침 없이 결과 표시)
2. 동기화 로그 화면 (`SyncLog` 시간 역순, 파일별 결과)
3. `python manage.py sync_all` 관리 명령어
4. mtime 변경 감지 통합 테스트

**완료 기준**
- 수동 동기화 시 변경된 파일만 재파싱 (다른 파일은 `no_change`)
- 동기화 로그에서 실패한 파일을 색상으로 구분 + detail 메시지 노출

### Phase 5 — E2E + 매뉴얼

**목표**: 사용자가 실제 사용 흐름을 검증하고 매뉴얼을 갱신.

**핵심 작업**
1. E2E 테스트 (Playwright 또는 Django LiveServerTestCase)
   - 시나리오: 등록 → 목록 → 4개 탭 순회 → 동기화 → 미갱신 경고 확인
2. 화면 캡처 → `docs/매뉴얼.html` 갱신
3. README.md 사용 가이드 보강

**완료 기준**
- E2E 테스트 5개 시나리오 모두 통과
- `docs/매뉴얼.html` 에 7개 화면 캡처 모두 포함

## 4. 리스크 및 완화

| 리스크 | 영향 | 완화 |
|---|---|---|
| 프로젝트마다 md 형식이 달라 파싱 실패 | 데이터 불완전 | `raw_text` 필드 보존, 파싱 실패도 SyncLog 에 기록 |
| 외부 폴더에 실수로 쓰기 | 사용자 데이터 손상 | agents.md 절대 금지 규칙 + 코드 리뷰 시 점검 |
| Tailwind CDN 버전 차이 | 스타일 깨짐 | 버전을 `base.html` 에 명시 + Phase 5 에서 `django-tailwind` 검토 |
| mtime 비교가 타임존 이슈로 부정확 | 불필요 재파싱 | `timezone.make_aware` 사용 + 통합 테스트로 검증 |
| SQLite 동시성 한계 | 대량 프로젝트 등록 시 lock | 단일 사용자 도구이므로 허용. 다중 사용자 확장 시 PostgreSQL 검토 |

## 5. 비목표 (Non-Goals)

다음은 v1.0 범위에 포함하지 않는다:

- 코드 라인 수, 커밋 수 등 개발 통계
- Slack/Telegram/Synology 알림(외부 통보) — 하네스 자체 hook 으로 충분
- 사용자 인증·권한 (다중 사용자 확장 시점에서 검토)
- 외부 프로젝트 폴더 쓰기 / 파일 생성 / docs 자동 보정 (절대 금지)
- 파이차트 / 도넛차트 / 활동 지수 등 시각화
