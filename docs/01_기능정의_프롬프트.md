### 프로젝트 개요

**harness-dashboard** 는 Claude Code 하네스가 적용된 프로젝트들을 한 곳에서 관리하는 웹 대시보드다.

핵심 가치:
- 프로젝트 폴더를 등록하면 해당 프로젝트의 하네스 문서들(feature_map.md, 기능정의.md, 프로그램구조.md, uiux개선.md 등)을 자동으로 읽어 구조화된 데이터로 변환한다.
- 여러 프로젝트를 한 화면에서 비교하고 각 프로젝트의 진행 상황을 파악한다.
- 억지스러운 통계는 배제하고, 실제 개발자가 매일 필요한 정보만 표시한다.

---

### 1단계 — 원본 데이터 분석

아래 파일들을 Read 도구로 읽어라:

```
docs/raw/기능정의.md
docs/raw/프로그램구조.md
docs/raw/프로젝트설계.md
docs/raw/uiux개선.md
```

읽은 후 다음 항목들을 파악한다:

**기능정의.md 에서 추출할 것:**
- 전체 SCR-* (화면 ID) 목록과 URL
- 전체 F-* (기능 ID) 목록과 구현 상태
- 앱별 기능 분포

**프로그램구조.md 에서 추출할 것:**
- 앱 목록과 각 앱의 책임
- 모델 목록과 주요 필드
- 서비스 함수 목록

**uiux개선.md 에서 추출할 것:**
- P0/P1/P2/P3 항목 수
- Phase별 완료(✅)/미완료([ ]) 체크리스트 항목
- 완료율 계산 가능한 구조

**프로젝트설계.md 에서 추출할 것:**
- Phase 목록과 각 Phase 의 목표
- 현재 진행 Phase

### 2단계 — 데이터 구조 설계

원본 md 파일들은 프로젝트마다 형식이 다를 수 있다.
대시보드에서 사용할 **일관된 SQLite 스키마** 를 아래 기준으로 설계한다.

#### 핵심 테이블 설계 원칙
- 원본 md 파일의 형식이 바뀌어도 파싱 로직만 수정하면 되도록 파싱 레이어를 분리한다.
- raw 텍스트도 함께 저장해서 파싱 실패 시 원문 확인이 가능하게 한다.
- 마지막 동기화 시각을 기록해서 변경 감지가 가능하게 한다.

#### 설계할 테이블 목록

```
Project          — 등록된 프로젝트 (경로, 이름, 마지막 동기화)
Screen           — SCR-* 화면 ID 목록
Feature          — F-* 기능 ID 목록 (구현상태 포함)
AppModule        — 앱/모듈 구조
Model            — 모델 정보
Phase            — Phase 목록과 진행 상태
ImprovementItem  — P0~P3 개선 항목 (완료 여부 포함)
SyncLog          — 동기화 이력 (언제, 어떤 파일, 변경 여부)
```

각 테이블의 필드를 구체적으로 정의하고 `docs/기능정의.md` 에 스키마를 기록한다.

---

### 3단계 — 화면 설계 (실용적인 대시보드)

아래 원칙을 지켜 화면을 설계한다:

**표시할 것 (실제로 유용한 것)**
```
프로젝트 목록 카드:
  - 프로젝트명 + 경로
  - 현재 진행 중인 Phase
  - 미완료 DoD 항목 수 (빨간 배지)
  - 마지막 동기화 시각
  - 미갱신 문서 경고 (pending_updates.json 연동)

프로젝트 상세 — 탭 구조:
  탭 1. 기능 현황
    - SCR-* / F-* 전체 목록
    - 구현완료 / 미구현 필터
    - 앱별 그룹핑
  탭 2. Phase 진행
    - Phase 목록과 완료율 (체크리스트 기반)
    - 현재 Phase 강조
    - 완료된 항목 ✅ / 미완료 [ ]
  탭 3. 프로그램 구조
    - 앱 목록과 각 앱의 모델/서비스 요약
    - feature_map.md 의 기능↔파일↔DB 매핑 테이블
  탭 4. 개선 항목 (P0~P3)
    - 우선순위별 필터
    - 완료/미완료 토글
```

**표시하지 않을 것 (억지스러운 통계)**
```
- 코드 라인 수
- 커밋 횟수
- "생산성 점수" 같은 의미없는 수치
- 파이 차트로 만든 완료율 (숫자로 충분)
```

### 4단계 — 기능 ID 정의

위 분석을 바탕으로 아래 형식으로 `docs/기능정의.md` 를 작성한다.

#### 화면 ID 체계
```
SCR-PROJ-01   프로젝트 목록 (대시보드 홈)
SCR-PROJ-02   프로젝트 등록/편집
SCR-PROJ-03   프로젝트 상세 — 기능 현황 탭
SCR-PROJ-04   프로젝트 상세 — Phase 진행 탭
SCR-PROJ-05   프로젝트 상세 — 프로그램 구조 탭
SCR-PROJ-06   프로젝트 상세 — 개선 항목 탭
SCR-SYNC-01   동기화 실행 및 로그
```

#### 기능 ID 체계
각 화면의 기능을 `F-{앱}-{번호}` 형식으로 정의한다.

### 5단계 — 파싱 전략 정의

각 문서 유형별 파싱 전략을 기능정의서에 포함한다:

#### 기능정의.md 파싱
```
- ## N. 섹션 제목 패턴으로 화면 추출
- | SCR-XXX | 패턴으로 화면 ID 추출
- | F-XXX | 패턴으로 기능 ID 추출
- 파싱 실패 항목은 raw_text 필드에 원문 저장
```

#### uiux개선.md 파싱
```
- ### [P0]/[P1]/[P2]/[P3] 패턴으로 개선 항목 추출
- ### ✅ 패턴으로 완료 항목 구분
- Phase별 체크리스트: - ✅ / - [ ] 패턴
```

#### 프로그램구조.md 파싱
```
- ## N. 섹션으로 앱 구분
- 모델명: class 패턴 또는 테이블 정의 추출
- 서비스 함수: def 패턴 또는 함수 목록 테이블 추출
```

#### 변경 감지
```
- 각 파일의 mtime (수정시각) 을 SyncLog 에 기록
- 다음 동기화 시 mtime 비교 → 변경된 파일만 재파싱
- 변경 없으면 "최신 상태" 표시
```

### 6단계 — 기능정의서 작성

위 내용을 종합하여 `docs/기능정의.md` 파일을 아래 구조로 작성한다:

```
# harness-dashboard 기능정의서

## 1. 시스템 개요
## 2. 화면 ID 체계 (SCR-*)
## 3. 기능 ID 체계 (F-*)
## 4. 데이터 모델 (SQLite 스키마)
## 5. 파싱 전략
## 6. 권한 구조
## 7. Phase 계획
```

작성 완료 후:
1. `docs/feature_map.md` 의 기능 매핑 테이블을 갱신한다.
2. `docs/프로그램구조.md` 의 앱 구조 섹션을 초기화한다.
3. `tmp/telegram_pending.txt` 에 완료 알림을 작성한다.

## 사용 방법

1. Claude Code 터미널에서 harness-dashboard 프로젝트 폴더로 이동
2. 원본 md 파일들을 `docs/raw/` 폴더에 복사
   ```
   mkdir -p docs/raw
   cp /path/to/기능정의.md   docs/raw/
   cp /path/to/프로그램구조.md docs/raw/
   cp /path/to/프로젝트설계.md docs/raw/
   cp /path/to/uiux개선.md   docs/raw/
   ```
3. 위 프롬프트 전체를 Claude Code 에 붙여넣기
4. 기능정의서 생성 완료 후 다음 프롬프트(프로그램 구현)로 이어간다
