## 1. 시스템 개요

### 1.1 목적

Claude Code 하네스가 적용된 프로젝트들의 **기능정의.md, 프로그램구조.md, uiux개선.md, feature_map.md, 프로젝트설계.md** 파일을 읽어 구조화된 데이터(SQLite)로 변환하고, 여러 프로젝트의 진행 상황을 한 화면에서 파악하는 관리 도구.

### 1.2 핵심 사용 시나리오

```
1. 사용자가 프로젝트 폴더 경로를 등록한다.
2. 대시보드가 해당 폴더의 docs/ 파일들을 파싱해서 SQLite 에 저장한다.
3. 이후 파일이 변경되면 "동기화" 버튼 또는 자동 mtime 비교로 갱신한다.
4. 여러 프로젝트의 Phase 진행률, 미완료 DoD, 미구현 기능, 미갱신 문서를 한 눈에 본다.
```

### 1.3 표시 원칙

**표시한다:**
- 현재 진행 중인 Phase 와 텍스트 기반 완료율 (예: `5/8 완료`)
- 미완료 DoD / `tmp/pending_updates.json` 항목 수
- 미구현 기능(F-*) 목록과 우선순위(P0~P3)
- 마지막 동기화 시각과 변경 여부

**표시하지 않는다 (Don'ts):**
- 코드 라인 수, 커밋 횟수 등 개발 생산성 수치
- 파이차트 기반 단일 완료율 (텍스트로 충분)
- 의미없는 "활동 지수" / "생산성 점수" 류 통계

### 1.4 사용자/권한

- **단일 사용자 로컬 도구** — 인증 없음. 모든 프로젝트에 접근 가능.
- 향후 다중 사용자 확장 시 Django session 인증 + Project 단위 권한 추가 (별도 Phase).

## 4. 데이터 모델 (SQLite 스키마)

### 4.1 설계 원칙

- 원본 md 파일 형식이 프로젝트마다 달라도 파싱 레이어만 수정하면 된다.
- 모든 파싱 산출물 모델은 `raw_text` 필드를 가진다 — 파싱 실패 시 원문 복구·재파싱 가능.
- mtime 으로 변경 감지, 불필요한 재파싱 방지.
- Django ORM 사용. 마이그레이션은 `apps/<app>/migrations/` 에 생성.

### 4.2 테이블 명세

#### Project (프로젝트)
```sql
CREATE TABLE project (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    name            TEXT NOT NULL,                     -- 프로젝트명
    path            TEXT NOT NULL UNIQUE,              -- 절대 경로 (예: D:\devshinhee\inidk)
    description     TEXT,
    last_synced_at  DATETIME,                          -- 마지막 동기화 시각
    created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
    deleted_at      DATETIME                           -- 소프트 딜리트
);
CREATE INDEX idx_project_active ON project(deleted_at) WHERE deleted_at IS NULL;
```

#### Screen (화면 ID)
```sql
CREATE TABLE screen (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    screen_id   TEXT NOT NULL,                         -- SCR-BNK-01, SCR-PROJ-01 ...
    category    TEXT,                                  -- 임상자원은행, 프로젝트관리 등
    name        TEXT,                                  -- 화면명
    url         TEXT,                                  -- URL 패턴
    raw_text    TEXT,                                  -- 원문 (파싱 실패 복구용)
    UNIQUE(project_id, screen_id)
);
```

#### Feature (기능 ID)
```sql
CREATE TABLE feature (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    screen_id   TEXT,                                  -- 연결된 SCR-* (FK 아님 — 문자열)
    feature_id  TEXT NOT NULL,                         -- F-BNK-01
    name        TEXT,
    status      TEXT DEFAULT 'unknown',                -- implemented / not_implemented / unknown
    priority    TEXT,                                  -- P0/P1/P2/P3
    raw_text    TEXT,
    UNIQUE(project_id, feature_id)
);
CREATE INDEX idx_feature_status ON feature(project_id, status);
```

#### AppModule (앱 모듈)
```sql
CREATE TABLE app_module (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    app_name      TEXT NOT NULL,                       -- boards, biobank, dashboard 등
    responsibility TEXT,                               -- 앱 책임 한 줄 설명
    model_count   INTEGER DEFAULT 0,
    service_count INTEGER DEFAULT 0,
    raw_text      TEXT,
    UNIQUE(project_id, app_name)
);
```

#### Model (모델 정보)
```sql
CREATE TABLE model_info (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    app_name    TEXT,                                  -- 소속 앱명
    model_name  TEXT NOT NULL,                         -- 클래스명 (예: Project, Feature)
    table_name  TEXT,                                  -- DB 테이블명
    fields      TEXT,                                  -- JSON 직렬화된 필드 목록 [{"name":"path","type":"TEXT"}, ...]
    raw_text    TEXT,
    UNIQUE(project_id, app_name, model_name)
);
```

#### Phase (Phase 정보)
```sql
CREATE TABLE phase (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    phase_num   INTEGER,                               -- 1, 2, 3 ...
    name        TEXT,                                  -- "Phase 1 — 기반 설정"
    goal        TEXT,                                  -- Phase 목표 (프로젝트설계.md 출처)
    status      TEXT DEFAULT 'pending',                -- done / in_progress / pending
    total_items INTEGER DEFAULT 0,                     -- 체크리스트 총 개수
    done_items  INTEGER DEFAULT 0,                     -- 완료 개수
    UNIQUE(project_id, phase_num)
);
```

#### ChecklistItem (Phase 체크리스트)
```sql
CREATE TABLE checklist_item (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    phase_id    INTEGER NOT NULL REFERENCES phase(id) ON DELETE CASCADE,
    project_id  INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    priority    TEXT,                                  -- P0/P1/P2/P3 (uiux개선.md 에서)
    content     TEXT NOT NULL,
    is_done     INTEGER DEFAULT 0,                     -- 0 미완료 / 1 완료
    raw_text    TEXT
);
CREATE INDEX idx_checklist_phase ON checklist_item(phase_id, is_done);
```

#### ImprovementItem (P0~P3 개선 항목)
```sql
CREATE TABLE improvement_item (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    priority      TEXT NOT NULL,                       -- P0/P1/P2/P3
    title         TEXT NOT NULL,
    description   TEXT,
    phase_target  TEXT,                                -- 구현 예정 Phase (선택)
    is_done       INTEGER DEFAULT 0,
    raw_text      TEXT
);
CREATE INDEX idx_improvement_priority ON improvement_item(project_id, priority, is_done);
```

#### FeatureMap (기능↔파일↔DB 매핑)
```sql
CREATE TABLE feature_map (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id    INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    feature_id    TEXT,                                -- F-BNK-01
    feature_name  TEXT,
    entry_point   TEXT,                                -- URL 또는 명령
    view_handler  TEXT,                                -- 파일경로:함수명
    service       TEXT,                                -- 서비스 파일:함수명
    model_db      TEXT,                                -- 테이블명 (필드, 필드)
    template_ui   TEXT,
    external_api  TEXT,
    raw_text      TEXT
);
CREATE INDEX idx_featuremap_project ON feature_map(project_id);
```

#### SyncLog (동기화 이력)
```sql
CREATE TABLE sync_log (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  INTEGER NOT NULL REFERENCES project(id) ON DELETE CASCADE,
    synced_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
    file_name   TEXT,                                  -- 파싱한 파일명 (예: 기능정의.md)
    file_mtime  DATETIME,                              -- 파일 수정 시각
    changed     INTEGER DEFAULT 0,                     -- 변경 여부 0/1
    result      TEXT,                                  -- success / failed / no_change
    detail      TEXT                                   -- 오류 내용 또는 파싱 요약 (예: "SCR 7건, F 20건 추출")
);
CREATE INDEX idx_synclog_project_time ON sync_log(project_id, synced_at DESC);
```

### 4.3 ER 요약

```
project (1) ──< screen
project (1) ──< feature
project (1) ──< app_module
project (1) ──< model_info
project (1) ──< phase ──< checklist_item
project (1) ──< improvement_item
project (1) ──< feature_map
project (1) ──< sync_log
```

> 모든 자식 테이블은 `project_id` 로 묶이며, Project 소프트 딜리트 시 cascade 삭제는 service 함수에서 명시 처리(`Project.objects.filter(...).update(deleted_at=now())` 후 자식 row 일괄 delete).

## 5. 파싱 전략

### 5.1 파싱 레이어 구조

```
apps/parsers/services/
├── base_parser.py          # 추상 BaseParser (parse(text) -> dict)
├── feature_parser.py       # 기능정의.md 파싱 → Screen, Feature
├── structure_parser.py     # 프로그램구조.md 파싱 → AppModule, ModelInfo
├── improvement_parser.py   # uiux개선.md 파싱 → ImprovementItem, ChecklistItem
├── design_parser.py        # 프로젝트설계.md 파싱 → Phase
└── feature_map_parser.py   # feature_map.md 파싱 → FeatureMap

apps/sync/services/
└── sync_service.py         # 오케스트레이션: mtime 검사 → 파서 호출 → SyncLog 기록
```

### 5.2 파일별 파싱 규칙

#### 기능정의.md
```
# SCR-* 추출
패턴: | SCR-{코드} | {구분} | {화면명} | {URL} |
예시: | SCR-BNK-01 | 임상자원은행 | 임상자원 확보 목록 | /biobank/resources/ |

# F-* 추출
패턴: | F-{코드} | {기능명} | {화면} | {상세} |
예시: | F-BNK-01 | 임상자원 목록 조회 | SCR-BNK-01 | ... |

# 섹션 구분
- "## N. " 으로 시작하는 헤딩 → 카테고리(category) 추출
- 파싱 실패 항목은 raw_text 필드에 원문 그대로 저장
```

#### uiux개선.md
```
# 개선 항목(ImprovementItem) 추출
패턴: ### [P{n}] {제목}        → is_done=0
      ### ✅ [P{n}] {제목}     → is_done=1
priority: P0 / P1 / P2 / P3

# Phase 체크리스트(ChecklistItem) 추출
패턴: ### Phase {n} — {설명}
항목: - ✅ {내용}   → is_done=1
      - [ ] {내용}  → is_done=0
      - [x] {내용}  → is_done=1 (소문자 x 호환)
```

#### 프로그램구조.md
```
# 앱(AppModule) 추출
패턴: ## N. apps/{앱명}/   또는   ### {앱명} 앱

# 모델(ModelInfo) 추출
패턴: class {ModelName}    또는   테이블명 셀 (| 모델명 |)
주요 필드: ``` 코드 블록 내 필드 정의 또는 표 row

### 5.3 변경 감지 알고리즘

```python
# apps/sync/services/sync_service.py
import os
from django.utils import timezone

def sync_one_file(project, filename: str) -> str:
    filepath = os.path.join(project.path, "docs", filename)
    if not os.path.exists(filepath):
        SyncLog.objects.create(
            project=project, file_name=filename,
            result="failed", detail="file not found",
        )
        return "failed"

    file_mtime = timezone.make_aware(
        datetime.fromtimestamp(os.path.getmtime(filepath))
    )
    last = (SyncLog.objects.filter(project=project, file_name=filename)
            .order_by("-synced_at").first())

    if last and last.file_mtime == file_mtime and last.result == "success":
        SyncLog.objects.create(
            project=project, file_name=filename,
            file_mtime=file_mtime, changed=0, result="no_change",
            detail="mtime unchanged",
        )
        return "no_change"

    # 변경됨 → 파서 호출 → 기존 row 삭제 후 재생성
    parser = PARSER_REGISTRY[filename]   # filename → Parser class
    text = open(filepath, encoding="utf-8").read()
    summary = parser.parse_and_save(project, text)

    SyncLog.objects.create(
        project=project, file_name=filename,
        file_mtime=file_mtime, changed=1, result="success",
        detail=summary,                  # "SCR 7건, F 20건"
    )
    return "success"
```

### 5.4 파싱 실패 시 동작

- 정규식 매칭 실패 → 해당 라인을 무시하지 않고 `raw_text` 필드에 누적해 저장.
- 전체 파일 파싱 중 예외 발생 → 트랜잭션 롤백, `SyncLog.result='failed'` + `detail` 에 traceback 요약(상위 1~2 라인).
- 파일 자체가 없음 → `result='failed'`, `detail='file not found'`. 동기화 자체는 계속 진행(다른 파일은 처리).
